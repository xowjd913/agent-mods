# 메모 (memo)

오른쪽 패널에서 메모를 쓰고, 마음에 드는 메모는 버튼 하나로 PO 터미널에 보내거나 GitHub 저장소에 올립니다. 메모 하나는 **폴더 안의 `.md` 파일 하나**라서, 다른 편집기로 고쳐도 되고 폴더째 백업하거나 동기화해도 됩니다.

- **이런 사람에게**: 떠오른 생각을 바로 적어 두었다가 PO에게 "이거 해 줘"로 넘기고 싶은 사람.
- **어디에 저장되나**: 내가 고른 폴더. 처음에는 `~/Documents/Herdr Memos`(Windows는 `%USERPROFILE%\Documents\Herdr Memos`)입니다. 폴더가 없으면 첫 메모를 저장할 때 만듭니다.
- **GitHub**: 메모마다 `GitHub에 올리기`를 눌러 정해 둔 저장소에 올립니다. 로그인은 터미널의 `gh auth login` 하나뿐입니다([아래](#github에-올리기)).
- **Google Drive는 이 모드가 로그인하거나 올리지 않습니다.** Google Drive 데스크톱 앱의 동기화 폴더(예: `내 드라이브` 안의 폴더)를 메모 폴더로 고르면 Drive 앱이 알아서 올려 줍니다. OneDrive·iCloud Drive도 같은 방식입니다.

## 사용법

### 목록

패널을 열면 메모 폴더의 `.md` 파일이 **고친 시각이 최근인 순서**로 나옵니다. 위 칸에는 제목, 아래 칸에는 본문 앞부분이 보입니다.

- **제목**은 글 안의 첫 `# 제목` 줄입니다. 없으면 첫 줄이 제목입니다. 비어 있으면 `제목 없음`입니다.
- 폴더 안에서 다른 프로그램으로 파일을 더하거나 고쳐도 목록은 몇 초 안에(또는 새로고침을 누르면 바로) 따라옵니다.
- 맨 위 폴더 줄에서 `폴더 바꾸기`로 폴더를 고르고, `기본 폴더로`로 되돌립니다. 폴더 줄에는 Google Drive 안내가 함께 보입니다.

### 쓰기·고치기·지우기

- `새 메모`: 빈 글쓰기 화면이 열립니다. 저장하면 `2026-11-27 1530 제목.md` 같은 이름의 파일이 생깁니다. 파일 이름에 못 쓰는 글자(`\ / : * ? " < > |`)는 공백으로 바뀌고, **같은 이름이 있으면 `(2)`를 붙여 새로 만듭니다. 기존 메모 파일을 덮어쓰지 않습니다.**
- 목록에서 메모를 누르면 고치는 화면이 열립니다. 저장해도 파일 이름은 그대로입니다.
- 고치는 사이에 **다른 곳에서 같은 파일이 바뀌었다면** 저장하지 않고 알려 줍니다. `내 글로 덮어쓰기`나 `바깥 글 불러오기` 중에서 고릅니다.
- 저장하지 않은 글이 있는 채로 목록으로 나가려 하면 한 번 더 묻습니다.
- `삭제`는 확인 줄이 뜨고, 확인하면 그 파일을 지웁니다(휴지통으로 가지 않습니다).

### PO에게 보내기

고치는 화면의 `PO에게 보내기` 버튼은 저장된 메모를 PO 터미널에 **내가 직접 친 입력처럼** 붙여 넣고 Enter까지 누릅니다. `hc send`를 쓰지 않아서 `<hc from=…>` 머리말이 붙지 않습니다([inbox](inbox.md)가 PO에게 보내는 길과 같습니다).

1. 저장하지 않은 글이 있으면 먼저 저장하라고 알려 줍니다.
2. 확인 줄에 **받을 PO 주소**가 보입니다. `보내기`를 눌러야 갑니다.
3. 보내는 글은 `메모 요청: <제목> — <본문> (파일: <경로>)` 한 줄입니다. 줄바꿈은 ` ⏎ `로 접히고, 본문이 1500자를 넘으면 잘라 `…(이하 생략, 파일 참고)`를 붙입니다. 파일 경로는 항상 붙으니 PO가 나머지를 읽을 수 있습니다.
4. 받을 PO는 `role=po` 라벨이 붙은 터미널입니다([inbox](inbox.md)의 이름 규칙과 같습니다). PO가 없거나 둘 이상이거나, PO가 일하는 중이거나, **PO가 칸으로 열려 있지 않으면** 보내지 않고 이유를 알려 줍니다.
5. 순서는 클립보드에 복사 → PO 칸으로 포커스 이동 → 붙여 넣기 → 잠깐 뒤 Enter → 키보드 포커스를 원래 칸으로 되돌림입니다. 그 사이 PO가 질문 중이 되면 Enter는 누르지 않고 글만 입력칸에 남깁니다. 클립보드에는 보낸 글이 남습니다.
6. 보내기 직전과 지우기 직전에는 목록을 읽은 폴더와 지금 폴더가 같은지, 파일이 그 폴더 바로 아래에 있는지 다시 확인하고, 폴더가 바뀌었으면 거절합니다.

### GitHub에 올리기

메모 파일을 GitHub 저장소의 폴더에 올립니다. **[GitHub CLI(`gh`)](https://cli.github.com)가 설치되어 있고 로그인되어 있어야 합니다.** 이 모드는 토큰을 읽거나 저장하거나 넘기지 않고(`GH_TOKEN`도 다루지 않음), `gh`가 가진 로그인만 씁니다.

1. 처음 한 번, 터미널에서 `gh auth login`을 합니다.
2. 목록 화면의 `GitHub 올리기` 줄에서 `설정`을 눌러 세 가지를 적고 `저장`합니다. 설정은 메모 폴더 설정과 같은 `config.json`에 저장됩니다.
   - **저장소**: `owner/이름` (예: `me/notes`). `https://github.com/me/notes` 주소를 붙여 넣어도 됩니다.
   - **브랜치**: 비우면 저장소의 기본 브랜치입니다.
   - **폴더**: 저장소 안의 폴더. 비우면 `memos`입니다. `a/b`처럼 중첩도 되고 한글도 됩니다. `..`·`.`으로 시작하는 이름(`.git` 등)·윈도우에서 못 쓰는 이름은 거절합니다.
3. 메모를 열고(저장된 상태) `GitHub에 올리기`를 누릅니다. 확인 줄에 **올라갈 저장소·브랜치·경로**가 보이고, `올리기`를 눌러야 올라갑니다.

올라가는 곳은 `<폴더>/<메모 파일 이름>`이고, 파일 바이트가 그대로 올라갑니다. 커밋 메시지는 `메모 추가: <제목>` 또는 `메모 수정: <제목>`입니다.

- **같은 이름의 파일이 이미 있으면** 그 파일의 현재 버전을 받아 와서 **수정**으로 올립니다. 내용이 이미 같으면 올리지 않고 알려 줍니다. 저장소 쪽에 같은 이름의 폴더가 있으면 올리지 않습니다.
- **`gh`가 없거나 로그인이 안 되어 있으면** 올리지 않고 `터미널에서 gh auth login` 안내를 보여 줍니다.
- **공개 저장소**이면 확인이 **한 번 더** 나옵니다("누구나 볼 수 있고 기록에서 지우기 어렵다"). `공개 저장소임을 알고 계속`을 눌러야 올리기 확인으로 넘어갑니다. 올리기 직전에 도우미가 공개 여부를 다시 확인하고, 확인 표시 없이는 공개 저장소에 올리지 않습니다.
- 실패하면 짧은 이유가 나옵니다.

| 상황 | 안내 |
|---|---|
| 404 | 저장소를 찾지 못함(철자·접근 권한 확인), 또는 브랜치가 없음 |
| 403 | 권한 없음(그 저장소에 쓸 수 있는 계정인지, 브랜치 보호 여부) |
| 409·422 | 그 사이 같은 파일이 바뀌어 버전이 안 맞음. 다시 올리면 최신 파일 기준으로 고침 |
| 그 밖 | 연결 실패·시간 초과·GitHub 서버 오류를 구분해 알림 |

- 1 MiB보다 큰 메모는 올리지 않습니다(화면에서 여는 한도와 같습니다).
- `gh`는 쉘 없이 인자 배열로 실행해서 따옴표 문제가 없고, Windows의 `gh.exe`도 같은 방식으로 찾습니다. GUI 앱의 짧은 `PATH`에는 `gh`가 흔히 설치되는 폴더(macOS `/opt/homebrew/bin`·`/usr/local/bin`, Windows `Program Files\GitHub CLI`)를 뒤에 더해 찾습니다.
- 올릴 내용은 JSON 본문 임시 파일(소유자만 읽기)에 담아 `gh api -X PUT ... --input`으로 넘기고, 끝나면 지웁니다.

### 바로가기 키

탭 줄에 `메모` 버튼이 생깁니다. 키는 `keys.json`에 직접 더합니다(설치기는 `keys.json`을 건드리지 않습니다).

```json
{
  "cmd-shift-m": "tabs-mine.memo-new",
  "cmd-alt-m": "tabs-mine.memo"
}
```

- `tabs-mine.memo-new`: 패널을 열고 새 메모 화면으로 갑니다.
- `tabs-mine.memo`: 패널을 열고 목록으로 갑니다.
- 모드 이름이 `memo`가 아니라 `tabs-mine`인 것은, 키가 화면에 보이는 모드에만 닿는데 닫힌 패널은 보이지 않기 때문입니다. 늘 보이는 탭 줄이 받아서 패널을 열어 줍니다.

## 필요한 것

- Node.js
- GitHub에 올리려면 [GitHub CLI(`gh`)](https://cli.github.com)와 `gh auth login`
- 함께 설치되는 모드: [패널 버튼](tabs-mine.md)

## 설치

추가 모드라 기본 설치에는 들어가지 않습니다.

```sh
curl -fsSL https://raw.githubusercontent.com/xowjd913/agent-mods/main/herdr/install.sh | sh -s -- --add memo
```

```powershell
& ([scriptblock]::Create((irm https://raw.githubusercontent.com/xowjd913/agent-mods/main/herdr/install.ps1))) -Add memo
```

- 오른쪽 패널에 `memo-board`가 더해지고 탭 줄에 `메모` 버튼이 생깁니다.
- 폴더 설정은 `<설정 폴더>/memo/config.json`에 있습니다. `--remove memo`는 모드 폴더와 패널의 `memo-board`를 빼고, 설정과 **메모 파일은 남깁니다.**
- 빼는 방법과 다른 옵션은 [모드 골라 설치](../../herdr/README.md#모드-골라-설치)에 있습니다.

## 확인하지 못한 것

자동 시험은 파일 이름·제목·목록·PO 글 만들기·설치기와, GitHub 올리기의 설정 검사·경로/URL 만들기·요청 본문·오류 안내·올리기 흐름(`gh`는 모의로 갈음, 실제 저장소에는 올리지 않음)을 확인합니다. 아래는 실제 앱 화면에서 사람이 눌러 봐야 합니다.

- 글쓰기 칸의 입력과 저장·충돌 안내 줄이 보이는 모양
- 폴더 고르기 창과 Google Drive 동기화 폴더 선택
- `PO에게 보내기`가 실제 PO 터미널에 들어가는지, 그때 PO 입력에 찍히는 모양(`<hc from=…>` 머리말이 없고 한 줄로 들어가는지), 키보드 포커스가 원래 칸으로 돌아오는지
- 설정 입력 칸 세 개와 확인 줄(공개 저장소 2단계 포함)이 보이는 모양
- **실제 GitHub 저장소로의 올리기**(새 파일·같은 이름 수정·브랜치 지정·한글 파일 이름·공개 저장소). 자동 시험은 `gh`를 모의로 바꿨고 실제 `gh api` 호출은 한 번도 하지 않았습니다.
- `gh`가 없는 PC와 Windows에서의 동작(`gh.exe` 찾기)
- `cmd-shift-m`·`cmd-alt-m` 키가 패널을 여는지, 탭 줄 `메모` 버튼 모양
